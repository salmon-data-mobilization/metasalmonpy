# Parity deviations — metasalmonpy vs metasalmon

The mirror contract (see `AGENTS.md`) requires the same behaviour and
capabilities as metasalmon at the version this package claims — **not**
literal API mimicry. This register lists every deliberate difference; its
twin lives in the hub at `metasalmon/knowledge/parity-deviations.md`, and the
two must agree. An undocumented difference is a contract violation even when
the difference itself is fine (Brett, 2026-08-15).

Three kinds of entries:

- **Idiom** — same behaviour, Pythonic delivery.
- **Ahead** — Python already has semantics R adopted later (or improved on);
  R converges or stays.
- **Inapplicable** — the R behaviour has no Python counterpart, with the why.

| # | Kind | Difference | Why |
|---|---|---|---|
| 1 | Idiom | Errors are Python exceptions with actionable messages, not R cli conditions | Language idiom; same conditions trigger them |
| 2 | Idiom | Optional dependencies are extras (`metasalmonpy[eml]`, `[knb]`), not Suggests | Packaging idiom; same lazy-guard behaviour and install pointers |
| 3 | Idiom | Canonical ordering uses codepoint `sorted()`, not explicit C-collation flags | Python's default sort is already locale-independent; the *contract* (locale-independent deterministic output) is identical, and `locale.strxfrm` is banned |
| 4 | Idiom | Archive/EML/ORE parity is contract-level (structure, manifest, ordering, fail-closed), never byte-level | R's bytes come from zip-3.0.1/libxml2 formatters Python cannot and should not reproduce |
| 5 | Ahead | `infer_value_type` is public API here, internal in R | Was already exported at 0.1.6; removing it would break users for no capability gain |
| 6 | Ahead | A failed or empty ontology fetch raises; 0.1.6-era R returned an empty index | Failed lookup ≠ empty lookup; R adopted the same principle at 0.2.2 |
| 7 | Ahead | `is_statistical_modifier` is a real column in both term-index frames; R's TTL path carries it only inside `role_hints` | Saves the 0.3.0 milestone a retrofit; hint strings match R exactly |
| 8 | Inapplicable | No interactive term-request console, so R 0.2.0's cancel-must-not-submit semantics have no counterpart | Submission here is a single explicit function call with confirmation |
| 9 | Planned (0.1.8) | `write_sdp_methods` will not be implemented; registry read/validate only | The writer would exist only to be deleted at 0.3.0 in the same replay; logged in the S10 execplan |
| 10 | Idiom | The SSSOM embedded metadata header is parsed with a restricted YAML-subset parser (plain/quoted scalars, one-level block mappings, block sequences); R parses it with the `yaml` package | Dependency policy is pandas+requests only; the subset is exactly what the canonical writer emits and the SDP profile uses. Headers outside the subset raise the same "not valid YAML" report R gives malformed YAML. Canonical mapping-set bytes match R's under C collation (see row 20) (`.ms_sssom_canonical_bytes` parity is tested against R-generated fixtures) |
| 11 | Idiom | `mapping-sets.json` provenance records `metasalmonpy.write_sdp_sssom` + `metasalmonpy_version`; `validate_sdp_sssom` accepts either implementation's provenance (metasalmon accepts metasalmonpy provenance since PR #43; each validator now accepts either) | Honest provenance: a manifest must name the writer that produced it. Dual acceptance keeps R-written SDPs valid here. Everything else in the manifest — entry fields, sha256 binding, radix `mapping_set_id` ordering — matches R exactly; the mapping-set TSV artifacts themselves are byte-identical |
| 12 | Idiom | `measurement-decompositions.json` provenance records `metasalmonpy.write_sdp_measurement_decompositions` + `metasalmonpy_version`; the validator accepts either implementation's provenance (metasalmon accepts metasalmonpy provenance since PR #43; each validator now accepts either) | The same honest-provenance ruling as row 11, applied to the 0.1.7 decomposition artifact. The artifact binding (path, sha256, row_count) and the decomposition CSV bytes themselves are byte-identical to R's (asserted against R-generated fixtures in `tests/data/decompositions/`) |
| 13 | Ahead | A dangling symlink at a managed output path is treated as existing (blocked without `overwrite`, then refused as a symlink) in `write_sdp_sssom` and `write_sdp_measurement_decompositions`; R's `file.exists()` misses dangling symlinks and silently writes through/over them | Fail-closed writer safety: a symlink the writer did not create should never be replaced implicitly. Read-side symlink handling matches R exactly (only resolvable symlinks are refused; dangling ones surface as missing files) |

| 14 | Idiom | The EML mapping sidecar is parsed with PyYAML (in the `[eml]` extra), not the restricted YAML-subset parser used for SSSOM headers | The sidecar is genuinely nested (creators, contacts, per-table attribute configs), unlike the flat SSSOM header; R uses `yaml::read_yaml` here too. Core dependencies stay pandas+requests |
| 15 | Idiom | EML documents are built with stdlib ElementTree and validated with lxml; parity with R is structural (`ET.canonicalize`), not byte-level | R serializes through libxml2, so whitespace differs while the documents are identical. lxml IS libxml2 — the engine behind `emld::eml_validate` — so accept/reject matches R by construction, and all UUIDv5 identifiers match exactly |
| 16 | Idiom | The KNB adapter speaks the DataONE v2 REST API directly with `requests`; R's default adapter delegates to `dataone`/`datapack`. The adapter boundary is a class with exactly the fourteen v0.1.7 methods, injected through `set_knb_adapter()` instead of R's `metasalmon.knb_adapter` option, and the JWT is supplied through `set_dataone_token()` instead of R's `dataone_token` option | There is no maintained Python `dataone`/`datapack`, and R already bypasses them for the ORE, the anonymous probes, the format registry, and the Solr catalog. Consequences of speaking REST directly, all behaviour-preserving: the production CN base URL is an explicit constant (R resolves it through `D1Client`); `update_object` uses the spec resource path `PUT /object/{oldPid}` where R's `dataone` client PUTs to `/object` with `pid` as a form field; `authoritativeMemberNode` is filled in `_system_metadata_document` (whose `node_id` argument R accepts and leaves unused) because R lets `dataone::createObject()` attach it at the upload boundary — the uploaded documents are `ET.canonicalize`-equal to R's; and the JWT claim decode is stdlib base64+json, matching R's unverified local check (the real check is server-side `echoCredentials`), so no PyJWT |
| 17 | Idiom | The deterministic SDP ZIP has its own Python determinism reference (`metasalmonpy-zipfile-1`: radix member order, 2000-01-01 timestamps, 0644, Unix `create_system`, no directory entries, deflate level 9) instead of R's `zip` 3.0.1 version pin, and its bytes are not comparable to R's | Row 4 applied to the archive. miniz (R's `zip`) and zlib emit different deflate streams, so byte parity is impossible without vendoring a compressor. The pin's *purpose* — a compressor change must be a reviewed package change, because the archive checksum is an immutable DataONE PID input — is kept by asserting the reference sha256 in `tests/data/knb/expected.json`; there is no runtime version abort because zlib ships with the interpreter and cannot be pinned per platform |
| 18 | Idiom | Because the ZIP (row 17), the EML document (row 15) and the ORE document (row 4) differ from R's *bytes*, an end-to-end Python plan for the same SDP yields a different archive PID, resource-map PID and `plan_sha256` than R's | Unavoidable and disclosed, not silent: every algorithm that derives those values is asserted byte-exact against R by driving the planner from R's own member table (`tests/data/knb/r/`) — the resource-map PID preimage, the ORE graph, the fingerprint payload encoding and its SHA-256, and the recovery-manifest JSON bytes. A manifest written by one implementation is therefore reviewed and published by that same implementation, exactly as DataONE immutability already requires |

| 19 | Idiom | `publish_sdp_to_knb(confirm=...)` defaults to `None`, not R's `interactive()` + `missing(confirm)` pair | R needs both halves to guarantee that an interactive default can never authorize a live call; a `None` sentinel expresses the same rule in one place. The contract is unchanged and identical: live mode proceeds only when the caller passed exactly `True` |

| 20 | Ahead | Canonical SSSOM ordering (curie-map prefixes, mapping-set ids) is codepoint/C, not locale-collated. Era R (0.1.7/0.1.8) used bare `sort()`/`order()`, so its bytes and manifest order vary by `LC_COLLATE`; metasalmon adopted C collation at **0.3.0** | Python has the semantics R landed on — locale-independent and reproducible. **Interop hazard while it lasts:** an era-R package written in a non-C locale can fail this validator's manifest-ordering check, and vice versa (demonstrated both directions). The committed `tests/data/sssom/` fixtures were generated under `LC_COLLATE=C`; era R in `en_CA` produces different bytes. Converges when the replay reaches 0.3.0 |
| 21 | Ahead | Every SDP reader preserves a literal `"NA"`; only the empty field is missing. Era R used readr's `na = c("", "NA")` | A forward-port of metasalmon **0.2.4**'s canonical missing-value contract ("NA" is a real fisheries gear code), landed early because era behaviour combined with the already-forward-ported `package_io` reader made a literal-`"NA"` vocabulary row unsatisfiable — Python could not export a package R could. Converges when the replay reaches 0.2.4 |
| 22 | Idiom | Consequence of row 21: `_ERA_NA_TOKENS` still governs the EML raw-token audit of **data resources** (era `("", "NA")`), so a trimmed `NA` in a data column is parsed-missing while a `NA` in a sidecar is data | An internal split inherited from applying row 21 at the 0.1.7 milestone; it disappears at 0.2.4 |
| 23 | Idiom | `trim_ws` is an approximation of readr, not a transliteration: `skipinitialspace=True` plus a strip of readr's trim characters. Matches readr on every probed field shape except a leading **tab** before an opening quote (`\t"z"\t`), which readr unquotes and pandas does not | Narrow enough to document rather than chase; recorded so it is a known boundary and not a surprise |
| 24 | Idiom | Atomic writes go through a Python-only `atomic_io` module so artifacts get the umask default mode | R gets umask behaviour free from `writeBin`; Python's `tempfile.mkstemp()` hard-codes 0600, which would have shipped owner-only semantic artifacts |
