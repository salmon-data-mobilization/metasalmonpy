# B-341: refuse unknown tags in the semantic-closure sidecar reader

## Authority and boundary

Claimed from hub main `052279b` under token `a-8b23709cce768317`, after
`hub status B-341` showed ready, claimable, no blocker and no live claim.
This isolated Python branch started at main `7ad6139`. Brett's 2026-09-25
Q62 ruling says to refuse an `!expr` tag on every EML-sidecar path. B-341 is
the Python semantic-closure reader; the separately queued R half is B-340.
No numbered parity row, public signature, frozen row, ontology IRI, provider
path, dependency or version changes belong to this item.

`semantic_closure._mapping_paths()` previously swallowed every `yaml.safe_load`
exception and used both default paths even when an untagged sidecar declaration
named another path. This branch turns PyYAML's unknown-tag constructor error
into a `ValueError` that names `metadata/eml-mapping.yml`, before either
closure file or the sidecar can be written. All other exceptions and non-mapping
documents retain the reader's existing default fallback. Untagged declared
paths still direct both writes. Standard YAML tags PyYAML already understands
are not reclassified as unknown local tags by this change.

The EML and KNB writer's `eml._read_mapping_yaml()` already refuses unknown
tags. It also raises on malformed YAML and rejects duplicate keys, unlike the
closure reader's legacy fallback, so calling it here would broaden this claim.
The narrow constructor-error seam retires when those readers can share a parser
with the same malformed-sidecar behavior.
