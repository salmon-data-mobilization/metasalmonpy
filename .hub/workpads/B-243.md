## What changed, and where

- `semantics.py`
  - New `_search_once_per_call(search_fn)`. It keeps, for the life of one
    `suggest_semantics()` call, each answer to a `(query, role, sources)` call
    whose diagnostics name no source that did not answer, and hands a repeat of
    that call the kept answer instead of searching. The degraded test is
    `_search_failed_sources()` from `term_search.py`, applied to
    `result.attrs.get("diagnostics")`, which is the reading `find_terms()`
    applies before it caches. A search that raises keeps nothing, and its
    exception propagates as before.
  - `suggest_semantics()` makes one before its retrieval loop and the loop calls
    it where it called `search_fn`. The LLM retry passes still get the raw
    `search_fn` through `assess_semantic_suggestions()`, as in R.
  - Two Python-specific points, neither a difference in behaviour. **The kept
    answer is a copy, and a hit hands out a copy**, the discipline
    `find_terms()`'s `_term_cache` already follows. An R value cannot be changed
    in place by the row that receives it, and a pandas frame can. The loop copies
    before it changes anything today, so this changes nothing observable; it
    keeps each target's answer from depending on that. **The key is
    `(query, role, sources)` as received, looked up in a dict.** R narrows by
    query string and then compares with `identical()` so as not to hash; a dict
    lookup here is exact for the keys the loop passes, a `str`, a `str` and the
    tuple of `str` that `policy_sources()` returns. Sources keep their order. A
    call whose query is not a `str`, or whose key cannot be hashed, is passed
    straight through and never kept, as R passes through a query that is not a
    single string.
- `tests/test_semantic_retrieval_dedup.py` (new, 4 tests): the twin of
  `tests/testthat/test-semantic-retrieval-dedup.R`, on the same four-table
  fixture and the same counting search, plus two tests R does not have (the
  empty answer every source gave, and the lifetime of one call). The per-target
  reference is `suggest_semantics()` with `_search_once_per_call` patched to hand
  back the search it is given, so it is the loop as it ran on `ba1b54a`, and the
  comparison covers the whole returned object rather than R's column subset.
  **One case differs from R's in shape, not in what it pins**: the outage that
  lasts answers with no candidates, where R's answers with one. *Guards added*
  says why and what retires it.

## Found, not absorbed

1. **Candidate (metasalmonpy): `suggest_semantics()` raises at `pd.concat`
   whenever two or more candidate frames carry a DataFrame in `attrs`, and
   every `find_terms()` answer does.** Measured on `main` `ba1b54a` (Python
   3.11.15, pandas 3.0.6, both legs): two measurement columns, `sources=["ols"]`,
   the default `find_terms()` with `term_search._search_ols` patched to return
   one candidate, network refused at the socket:

   ```
   find_terms attrs keys: ['diagnostics'] DataFrame
   suggest_semantics raised ValueError: The truth value of a DataFrame is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().
   ```

   `find_terms()` sets `ranked.attrs["diagnostics"]`. The retrieval loop's
   `res.copy()`, filter, sort and `head()` all carry `attrs` along, so every
   candidate frame reaches `pd.concat(suggestion_rows)` with one. When every
   input has non-empty `attrs`, pandas' `NDFrame.__finalize__` compares them
   with `obj.attrs == attrs` (`pandas/core/generic.py:6170` in 3.0.6), and a
   DataFrame there has no truth value. So the default search path fails as soon
   as two targets get candidates. **`create_sdp()` with its defaults is one
   such path**, because `seed_semantics` defaults to `True` and no `search_fn`
   is passed down. The same machine and tree, every `term_search._search_*`
   source patched to answer one candidate, network refused:

   ```
   create_sdp raised ValueError: Can only compare identically-labeled (both index and columns) DataFrame objects; source calls before it: 52
     at package_io.py:2136 create_sdp: artifacts = infer_salmon_datapackage_artifacts(
     at package_io.py:1794 infer_salmon_datapackage_artifacts: dict_df = suggest_semantics(
     at semantics.py:1009 suggest_semantics: suggestions_df = pd.concat(suggestion_rows, ignore_index=True)
     at generic.py:6170 __finalize__: have_same_attrs = all(obj.attrs == attrs for obj in objs[1:])
   ```

   The message differs because those diagnostics frames differ in shape; the
   comparison is the same. `infer_dictionary(seed_semantics=True)` calls
   `suggest_semantics()` without a `search_fn` too, and was not run. The suite
   does not see any of it, because no test's search stub sets `attrs`. This
   change neither causes nor cures it: a kept answer is a copy, which carries
   `attrs` as the loop's own copy does. It is why the outage test answers with
   no candidates. Not measured on another pandas version, and R was not
   measured.

## Guards added, and what retires them

- **The outage that lasts answers with no candidates**, where R's answers with
  one. A one-candidate degraded answer for every target puts `attrs` on every
  candidate frame and stops `suggest_semantics()` at `pd.concat` before the
  test is reached (*Found*, item 1). With no candidates, no frame reaches
  `pd.concat`, and the calls are still counted. The case is the shape
  `find_terms()` itself returns when its only source fails. *Retires when:*
  the candidate frames reach `pd.concat` without the attrs of the search that
  returned them; the outage can then answer with a candidate, as R's does. The
  test says so where it happens.
- **`raising=False` on the reference's patch** is not a suppression. It lets
  one file run on a tree without the helper, which is how the RED run on
  `ba1b54a` was taken. If the helper is ever renamed, the patch lands on a name
  nothing reads, the reference stops searching once per target, and the first
  test's premise assertion and the empty-answer test's
  `len(set(keys)) < len(reference_keys)` both fail.
- No skip, suppression or allowlist was added.
