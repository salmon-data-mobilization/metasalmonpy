## What changed, and where

- `sdp_field_setters.py`, `_gaps_for_file()`. `add()` now keeps one gap row per
  field of each metadata row: it records each field it reports and returns
  without adding a row for a field already reported on that row. The field loop
  runs first, so a placeholder keeps the loop's `placeholder` row and a
  `REVIEW:` marker keeps the loop's `iri` row. A blank field the loop passes
  over is still reported by the `observation_unit_iri` or measurement-IRI
  branch, as `iri`, as before. The branches' predicate is unchanged
  (`_is_unfilled_metadata()`). The comment on the `observation_unit_iri`
  branch was rewritten. It said the prose test was what kept one field from
  being reported twice, and that was wrong for a prose placeholder.
- `tests/test_sdp_field_setters.py`: the new test, plus
  `_UNFILLED_IRI_STATES`. It plants a value in `tables.csv`
  `observation_unit_iri` and in the measurement row's `unit_iri`, asserts one
  row per field with the expected reason, executes every printed call with the
  module's existing `_run_printed_calls()`, and asserts both fields are gone.
- `CHANGELOG.md`: an entry under `## Unreleased`, `### Fixed`.
- `AGENTS.md`: the dated suite counts, re-measured on this branch in both legs.

The guard sits in `add()` rather than in the two branches. That makes "one row
per field of a row" hold for every branch rather than for the pair the item
names. `MetadataReview` already documents "one row per unfilled field", so this
is where that promise is kept. The by-product is measured below under *The

## Found, not absorbed

- **For B-211:** metasalmon's fix should keep one row per field whichever
  checks find it, as `add()` now does here. A fix that only narrowed the two
  branches to a blank test would close the placeholder route and leave the
  required-IRI route above open in R alone. That would then be a difference
  between the two packages, and it would need a parity row.
- **Candidate, no item yet: two metadata rows with one address print one call
  that repeats keywords.** `_render_metadata_lines()` groups gap rows by
  file, `table_id`, `column_name` and `code_value`. So a `column_dictionary.csv`
  carrying the `spawner_count` row twice gives one `set_sdp_column()` call
  that names each of that row's fields twice. Measured on `351fed6` with a
  scratch script: `SyntaxError: keyword argument repeated: column_description`.
  A duplicated key is a structural defect in its own right, and the setter
  refuses an ambiguous address. What this adds is that the printed call fails
  to compile before the setter can say what is wrong. This fix does not
  change it, because the guard is per metadata row. R was not measured.

## Guards added, and what retires them

- **`add()`'s one row per field of each metadata row.** It stops two branches
  reporting one field. It does not silence a signal: the field is still
  reported, once, under the first check that finds it. *Retires when:* nothing
  while `MetadataReview` promises one row per unfilled field and the printed
  call names each field as a keyword argument. If either changes, revisit it.
