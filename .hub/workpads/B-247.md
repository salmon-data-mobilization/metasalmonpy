## What changed and where

- **`review_console.py`, `_review_names_term()`**, new: the port of R's
  `.ms_review_names_term()`. It takes what `_strip_review_iri()` returns, which
  already trims, so it is what R's `.ms_review_decision_iri()` computes, and
  answers whether that names a term: not empty, and not still read as a marker
  by `_is_review_iri()`. The queue, the console and the refusal all read it.
- **`review_console.py`, `_recorded_decision()`**, new: the one reading of a
  `decision` cell. The replay, `_review_seed_recorded_decisions()`, now calls it
  instead of spelling the same lookup inline, with no change in what it reads,
  and the new reject mask below calls it too, so the two cannot disagree about
  which rows carry a recorded reject.
- **`review_console.py`, `review_semantics()`.** `has_iri` is the predicate,
  where the mask tested only that the text of `iri` was not empty. A row
  carrying a recorded reject is kept whatever its IRI. The list printed under
  *"Some suggestions target fields this review cannot decide"* is built from the
  rows with no write-back address or no IRI field (`~decidable`), where it was
  built from every dropped row (`~keep`).
- **`review_console.py`, `_render_review_lines()`.** No accept call is printed
  for a candidate whose IRI names no term; *"(its IRI names no term, so it
  cannot be accepted)"* is printed in its place, R's text.
- **`review_console.py`, `accept_suggestion()`.** The refusal calls the
  predicate on both routes. `rank=` on a candidate that names no term raises
  *"The candidate at that rank names no term. …"*, and `iri=` a value that is
  still a marker once one is stripped raises *"iri must be an IRI, not a
  REVIEW: marker. …"*. B-220's two messages are unchanged, byte for byte.
- **`tests/test_review_console.py`**, 48 tests, the twins of B-246's in
  `tests/testthat/test-review-console.R`:
  - (1) per spelling of `MARKER_ONLY_IRIS` (7): a candidate that is only the
    marker is not queued alone, so `rank=1` finds no slot; ahead of a real
    candidate it takes no rank, dropping it prints no "cannot decide", and
    `rank=1` records the real IRI.
  - (2) per spelling (7): a recorded `accepted` row whose `iri` is only the
    marker replays no accept with an empty `decision_iri`, and the slot is
    queued again, undecided.
  - (3) per spelling of `DOUBLED_MARKER_IRIS` (4): `iri=` refuses it; as a
    candidate it is not queued, so `rank=1` records the real candidate; a
    recorded accept of it replays no marker.
  - `rank=` in a review the current `review_semantics()` did not build (11,
    every spelling of both lists), with a queued candidate's `iri` edited to it.
  - A recorded reject (13: every spelling of both lists, an empty and a missing
    `iri`): replayed with its reason from `include_filled=True`, out of the
    default queue, and `rank=1` on it refused.
  - The console (4: `"REVIEW:"`, `"REVIEW: REVIEW:"`, empty, missing): beside a
    slot with a real candidate, a rejected slot whose only candidate carries the
    value shows `DECIDED: reject` and the note; the one accept call printed runs
    and records the real candidate, and both reject calls run.
  - (4) for an empty and a missing `iri` (2): the row is not reported under
    "cannot decide" and the slot's real candidate is queued; beside a
    `dataset.csv` `keywords` row the message still names `dataset.csv` and not
    `column_dictionary.csv`.
  - Each per-spelling test asserts its premise against this package's own strip
    and detector first, as B-220's do, and (1) and (2) reuse B-220's
    `MARKER_ONLY_IRIS` rather than a second list.
- **`CHANGELOG.md`**: a *Fixed* entry under `## Unreleased`.
- **`AGENTS.md`**: the dated suite counts, re-measured.

## Case by case, against B-246's rule

| case | B-246's rule in R | here |
|---|---|---|
| (1) | never queue such a candidate (`has_iri` is the predicate), so it takes no rank; `rank=` refuses one that a review it did not build still holds | the same, in `review_semantics()` and `accept_suggestion()` |
| (2) | no change of its own: the replay runs over queued rows only, so (1)'s line closes it | the same: `_review_seed_recorded_decisions()` runs on the rows built from the kept suggestions |
| (3) | refuse, and do not strip again: the predicate's detector term closes `rank=` and the replay, and `iri=` gets its own message | the same |
| (4) | build the report from `!decidable`, and drop a no-term row without a word | the same, from `~decidable` |
| B-246's Codex rounds | keep a recorded reject whatever its IRI; print no accept call the refusal would abort | the same |

No exported signature, return-value attribute or column changed. The review
frame has the same columns; `review_semantics()` returns fewer rows where a
candidate names no term, and `accept_suggestion()` refuses more values, as in R.
In a slot that held such a candidate the candidates after it rank one place
higher, the shape B-246's port note asks for.

**Differences of language, not of behaviour.** The messages are one string each,
R's cli bullets joined into sentences, as B-220's were, and the exception is the
`ValueError` the function already raises. The doubled list's "in two cases"
spelling is `review: Review:`, where R's twin is `review : Review:`: this
package's strip does not read a space before the colon as the marker today, and
which spellings count is Q-63's.

**One Python-specific point.** The reject mask reads the `decision` cell through
the replay's own reading, which lower-cases it here, where R's replay and R's
mask both read it as written. So in each package the mask agrees with that
package's replay. The case difference between the two replays predates this
change; it is under *Found, not absorbed*.

## Found, not absorbed

This reports what was looked at: the review console's queue, replay, refusal,
console and report, and the writer's handling of a saved accept. It does not
claim that nothing else is wrong.

1. **The Codex finding routed from metasalmon #199, measured here:
   `apply_sdp_semantics()` writes a saved accept that names no term.** Probed on
   `60144a1`, where the writer is as on `main`: a `create_sdp()` package seeded
   with a stubbed search (the `seeded_package` fixture's), its review's
   `spawner_count` variable row set by hand to `decision` `accept` with the
   `decision_iri` below, then applied:

   ```
   saved ''                : applied; term_iri 'REVIEW:https://w3id.org/smn/SpawnerAbundance' -> ''
                             semantic_suggestions.csv: ('user', '', 'accepted'), ('smn', <IRI>, 'not_selected')
   saved 'REVIEW:'         : applied; term_iri -> ''
                             semantic_suggestions.csv: ('user', 'REVIEW:', 'accepted'), ('smn', <IRI>, 'not_selected')
   saved 'REVIEW: REVIEW:' : applied; term_iri -> 'REVIEW:'
                             semantic_suggestions.csv: ('user', 'REVIEW: REVIEW:', 'accepted'), ('smn', <IRI>, 'not_selected')
   ```

   The first is the damage B-220 described, reached through a saved object, as
   B-246 measured in R. The writer strips one marker as it writes
   (`metadata_write.py`, the `frame.at[index, field] = ...` line), so a saved
   doubled marker writes a marker into `term_iri`. It is held for the next
   queue sweep, and a fix has the same choice R's has about a saved
   `REVIEW: <IRI>`, which the writer turns into a real IRI today.
2. **Candidate: the two review consoles read a recorded `decision` cell with
   different case rules.** Here `_review_seed_recorded_decisions()` lower-cases
   it; R's `.ms_review_seed_recorded_decisions()` matches it as written. Measured
   on a one-candidate slot, `include_filled=True`:

   ```
                               R (the library)    this branch       main c7be120
   <IRI>     "rejected"        reject             reject            reject
   <IRI>     "Rejected"        NA                 reject            reject
   <IRI>     "ACCEPTED"        NA                 accept            accept
   "REVIEW:" "rejected"        reject             reject            reject
   "REVIEW:" "Rejected"        no row             reject            reject
   "REVIEW:" "ACCEPTED"        no row             no row            accept
   ```

   So a `Rejected` or `ACCEPTED` typed by hand is a decision here and not in R.
   Within R the reading is not uniform either: `PARITY.md` row 31 records that
   `apply_semantic_suggestions(strategy = "reviewed")` reads `decision`
   case-insensitively in both packages. This change keeps each package's mask
   agreeing with its own replay and does not move either. Which side is right is
   open; no queue item for it was found by searching the hub's backlog,
   parity register and item files for the case handling of a decision cell.

## Guards added, and what retires them

- **The premise assertion in each per-spelling test.** (1) and (2) assert that
  the strip empties the spelling, (3) that what the strip leaves is still read
  as a marker, and the `rank=` test either. Each fails naming its spelling if
  the strip or detector changes, so a changed strip cannot leave a test that
  checks nothing. *Retires when* Q-63's ruling puts every detector here behind
  one predicate (B-345): the lists should then come from it, as B-220's list
  should.
- The queue filter, the silent drop in (4), the `rank=` refusal and the
  console's note are behaviour rather than guards: a candidate that names no
  term offers nothing to decide, and the call the note replaces could only
  fail, so nothing retires them.
