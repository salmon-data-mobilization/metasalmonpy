## Scope and hierarchy

Public `MetasalmonCondition` is the common base; `MetasalmonError` and
`MetasalmonWarning` are separate severity branches. Each has validation,
LLM, publication and retrieval families. They are exported at the package
root and documented in `guides/conditions.qmd` with navigation.

Thirty-three explicit private subclasses combine exactly one existing concrete
builtin/category with a public family. Builtin constructors remain inherited;
no factory, shadowed builtin, global exception handler, message rewrite or
control-flow change. Modules import private emission aliases; their existing
`except ValueError` and other dependency catches still refer to the builtins.

582 owned builtin error constructions, 44 warning sites and four existing
specialized bases are covered. The stored structural validation error retains
its `.issues` frame. `KnbHttpError.status`, `SdpSchemaError`,
`SdpExtensionError` and `ReproducibilityManifestError` remain intact. The
queue's “no condition classes anywhere” premise is historical: those four
specialized types already existed; the missing part was common selective
package/domain catches.

Domain assignment mirrors the R module boundary behaviorally: schema/dictionary,
SSSOM, SDP metadata extensions, semantic-file closure and reproducibility use
validation; model/chat adapters use LLM; KNB/EML/EDH/Darwin Core/GitHub use
publication; vocabulary fetchers use retrieval. Generic suggestion/review,
metadata writing, package assembly and other modules keep base-only families.
The guide explicitly notes that a structural validator in `package_io` uses
the package error base rather than classifying functions by their names.
