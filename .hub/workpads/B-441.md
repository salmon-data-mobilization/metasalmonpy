## What changed, and where

1. **Units named by a column-name suffix** (`semantics.py`).
   - New `_trailing_unit_token()` reads the last token of a label or name, as
     metasalmon's `trailing_unit_token()` does, with the same word lists:
     `mm`, `cm` and `kg` (and their spelled-out forms) are read directly; `m`
     and `g` only when a length word (`length`, `depth`, `height`, `width`,
     `distance`, `elevation`, ...) or a mass word (`weight`, `wt`, `mass`)
     comes before them. Parenthesised text is ignored and camel case splits.
     A compound unit is not read: a `/` before the last token
     (`mercury_mg/kg`), or a token before it that is `per` or another unit
     (`mercury_mg_kg`, `eggs_per_kg`), means the last token is only a
     ratio's denominator. This is the boundary B-440 drew, kept here.
   - `_measurement_query()`, unit role: after `unit_label`, the label and then
     the name are read for a trailing unit, in the order metasalmon's
     `extract_measurement_header_unit()` reads them, before the count
     fallback. Its `target_query_basis` is the new value `unit_suffix`.
   - `_semantic_discover_targets()`: a query read from the label or name
     (no description) drops a recognised unit token, so `fish_length_mm`
     searches for `fish length` in every role that searches the base query,
     as in R. A description is searched as written, as in R.
   - `_is_count_like_measurement()` returns False for text naming a physical
     quantity (length, weight, mass, depth, height, width, diameter, girth,
     distance, temperature) unless it also has an explicit count word, with
     R's regular expression.
2. **Temporal coverage ignores administrative dates** (`metadata.py`).
   - New `_is_administrative_date_column()`, with
     `.ms_is_administrative_date_column()`'s word lists, tokenizer (camel
     case, `_`, `.`) and glued-affix stripping (`DateCreated`, `processdate`,
     `lastmodified`). `entry`/`entered` is administrative only alone or as
     "data entry"; `river_entry_date` is an observation.
   - `infer_dataset_metadata_from_resources()` skips those columns before it
     takes the minimum and maximum. With only administrative dates the
     coverage stays blank.
3. **Positive-longitude review note** (`metadata.py`).
   - New `_longitude_sign_is_suspect()`: every longitude in [50, 180] and
     every latitude in [30, 75], R's window.
   - When it holds, `spatial_extent` becomes R's `REVIEW REQUIRED:` note, word
     for word, around the inferred extent, unflipped. The existing strict
     placeholder sweep handles the marker.

Tests: `tests/test_create_sdp_inference_cues.py`, the twins of metasalmon's
`tests/testthat/test-create-sdp-inference-cues.R`, one for one and in its order
(11 tests). Two existing pins moved with the behaviour, each re-measured

## Not done, and why

- **metasalmon's older measurement-header readers were never ported, and still
  are not.** R's `normalize_measurement_header_query()` lower-cases a header
  and removes parenthesised text. It also splits on ` / `, removes
  `in <unit>`, expands `temp`, `spd`, `dir`, `max`, `min` and `grnd`, and
  special-cases rainfall, snowfall, water level and discharge. R's
  `extract_measurement_header_unit()` reads a parenthesised unit, a header
  that is wholly a unit, and `in <unit>` before the trailing token.
  `paired_unit_query_from_data()` reads a `*value` column's sibling `*unit`
  column. All of these are in R's initial commit. metasalmonpy has none of
  them, and neither register names the gap. B-440 changed only the trailing
  token, and B-441's `retires_when` names only that, so porting the rest would
  widen this item. Measured consequences in the probe set:
  - `mm` gets no unit here, where R reads millimeter;
  - `temp_c` and `water_temp_degC` keep `temp` and get no unit;
  - `length_in_metres` now searches `length in`, where R searches `length`
    and `main` searched `length in metres`. This is the one shape where this
    item's port leaves a visible artifact. The unit, meter, now agrees.
  A header with both a parenthesised unit and a suffix unit that disagree
  would read the suffix here and the parenthesis in R. Before this change
  Python read neither.
- **Units beyond length and mass**, year-only temporal coverage, and the
  heuristic's known false positives (Japan, the Russian Far East) are as B-440
  left them, for the reasons its workpad gives.
- **The hub-side records** (the landed record in `knowledge/parity-deviations.md`
  and `knowledge/roadmap.md` that lint will want when B-441 is marked done)
  live in metasalmon, outside this claim. Their text is in the hand-back.

## Found here, belonging elsewhere

- **Candidate: port, or register, metasalmon's older measurement-header
  readers** (the list above). The divergence is unregistered, so it is either
  an owed port or a register row. Which one is Brett's call, not this item's.
- **Candidate: `spatial_extent` number rendering.** This package writes an
  integer-valued latitude as `60.0` where metasalmon writes `60`, because
  `str(float)` and R's `as.character()` differ. More generally R keeps 15
  significant digits. The difference predates B-441 and is unregistered. The
  twin tests compare the shared prefix (`lat=48.2..60`), or this package's own
  pre-existing string, and say why.
- **Candidate: `parity.yml` installs metasalmon's R dependencies with no
  system requirements.** It relies on Package Manager having a binary for
  every package. When CRAN is ahead, as it is now for `curl`, the job builds
  from source and fails for want of `libcurl4-openssl-dev`. Installing the
  system requirements, or the dependencies through
  `r-lib/actions/setup-r-dependencies`, would remove the dependence on
  that timing. A workflow change, so not absorbed here.
- **Candidate: measurement descriptions that are `REVIEW REQUIRED:`
  placeholders.** R ignores them when it builds the base query. This package
  ignores only `MISSING ...` and `REVIEW:` IRIs. Seen while reading, not
  measured.

## Guards added, and what retires them

- `_longitude_sign_is_suspect()` (the review note). Retires when the spatial
  extent is inferred from coordinates that declare their own sign convention
  (a geometry with a coordinate reference system, or an explicit hemisphere
  column), so a bare positive number is no longer the only evidence. The same
  text is in its docstring, as R's is in its comment.
- The one-letter `m`/`g` quantity-word gate, the compound-unit refusal and the
  `entry` qualifier rule limit new readers. They suppress nothing. Each is
  stated where it is written.
