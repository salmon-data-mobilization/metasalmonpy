## Implementation

`sssom._parse_scalar()` still handles quoted values first, then refuses
unquoted explicit YAML node tags through its existing not-valid-YAML failure.
Every top-level, nested mapping and block-sequence scalar reaches that gate.
The small `_scalar_has_yaml_tag()` detector also checks node-property positions
in flow values that the restricted parser otherwise retains as text, masking
complete quoted nodes and preserving ordinary plain-text exclamations. It does
not load YAML, resolve tags, evaluate expressions or change writer rendering.

An anchor can precede a tag and flow mapping keys can be quoted; the grammar
source is [YAML 1.2.2 section 6.9](https://yaml.org/spec/1.2.2/#69-node-properties).
The baseline public reader accepted `!foo X`, `!!str X`, `&a !foo X`,
`!<tag:yaml.org,2002:str> X`, `[!foo X]` and `{item: !foo X}` as title text.
Only checking a raw leading exclamation would therefore leave genuine tagged
flow values accepted. R B-352's owner agreed these paired source controls.

The existing package validator test retains both non-evaluation sentinels and
the read spy proving the installed mapping file was reached. Its old claim
that the parity choice was unruled is replaced with Q62, and the verdict now
must be ValueError/not-valid-YAML naming that file. No guard was disabled.
