## What changed, and where

- `sdp_field_setters.py`, `_render_metadata_lines()`: the footer counts the
  rows whose `field` ends in `_iri`, where it counted the rows whose `reason` is
  `iri`. This is the line metasalmon's `.ms_metadata_render_lines()` carries
  after B-211, `sum(grepl("_iri$", review$field))`. The suffix test is
  `str(field).endswith("_iri")`, the one the scan's marker branch in
  `_gaps_for_file()` applies, and like `grepl()` it does not trim. The comment
  above it is R's, with this item's id added and one sentence naming the
  suffix test.
- `tests/test_sdp_field_setters.py`: one test, the twin of R's `an IRI field
  reported as a placeholder still counts as an IRI in the console`. It plants
  `_UNFILLED_IRI_STATES["prose placeholder"]` (`MISSING METADATA:` in
  `tables.csv` `observation_unit_iri`, `REVIEW REQUIRED:` in the
  `spawner_count` row's `unit_iri`) on `filled_package`, a package filled by
  its own printed calls. It makes R's four assertions: the two fields, both
  `placeholder`, `   2 fields still block strict validation.`, and
  `   2 of them are IRIs -- review_semantics() shows candidates for any that
  have them.` It reads the console through `review.render_lines(path_expr="pkg")`,
  as R's reads `.ms_metadata_render_lines(review, path_expr = "pkg")`.
- `CHANGELOG.md`: one entry under `## Unreleased`, `### Fixed`.
- `AGENTS.md`: the dated suite counts, re-measured.

Every row the old count found has an `_iri` field: the scan gives reason `iri`
only in its marker branch, which requires the suffix, in the
`observation_unit_iri` branch, and in the branch over `MEASUREMENT_IRI_FIELDS`,
all four of which end in `_iri`. `_annotate_decisions()` changes `note` only. So
the count only gains rows, and only `_iri` rows reported under another reason.
