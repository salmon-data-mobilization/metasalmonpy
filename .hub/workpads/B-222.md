## What changed, and where

- `review_console.py`, `accept_suggestion()`: with `iri=` given, the decision
  goes on the first row in the slot whose IRI, read through
  `_strip_review_iri()`, equals the accepted IRI. That is the row
  `rank=<its rank>` uses. With no such row it goes on the slot's first row, as
  before. The `iri` parameter's docstring says so, as R's `@param iri` does.
- `review_console.py`, `_strip_review_iri()`: docstring only. It now says this
  is the one rendering the selection, the writer's check and the decision
  record all read, and that it is what R's `.ms_review_decision_iri()`
  computes.
- `metadata_write.py`, `apply_sdp_semantics()`: the `term_type` check compares
  `_strip_review_iri(row["iri"])` with the decision's IRI. Before, it compared
  `_text(row["iri"])`, which keeps a `REVIEW:` marker.
- `tests/test_review_console.py`: the `typed_package` fixture (an `smn`
  candidate at rank 1, an `owl_class` at rank 2) and five tests (four
  functions, one parametrized twice), twinning four of R's five B-221 tests.

**One rendering, with no new helper.** R needed `.ms_review_decision_iri()`
because its `.ms_strip_review_iri()` removes whitespace only around a marker
(`gsub("^\\s*REVIEW\\s*:\\s*", ...)`, `R/package-helpers.R`). Python's
`_strip_review_iri()` trims `READR_TRIM_CHARS` through `_text()` before it
strips, so it already computes what R's new helper computes. The record mask in
`_record_decisions()` and the rebuilt review's replay
(`_review_seed_recorded_decisions()`) already read a candidate's IRI through
it. So after this change the selection, the writer's check, the record and the
replay all read one function. A second name for it would have given two
spellings of one rendering.

## What was not done, and why

- **R's trailing-newline test is not twinned.** Its premise is that a quoted IRI
  keeps a trailing newline through the package's reader, and in Python it does
  not. Measured on this machine with one CSV whose `iri` field is
  `"https://example.org/ols/SpawnerCount\n"` (quoted), readr 2.2.0 under R
  4.3.3 returns `"https://example.org/ols/SpawnerCount\n"`, and `read_sdp_csv()`
  returns `'https://example.org/ols/SpawnerCount'`. The defect that test pins in
  R, a record mask that stripped the marker without trimming, has no Python
  counterpart either. `_record_decisions()` reads the IRI through
  `_strip_review_iri()`, which trims. So the port entry's "not the record" holds
  on `ed5e22e`.
- **The record mask is unchanged**, for the same reason.
- **`PARITY.md` is unchanged.** This closes R-shipped-first lag. It opens no
  deliberate difference.
- **No new helper named after R's.** See "One rendering, with no new helper"
  above.
- The landed record for this port in metasalmon's register and roadmap is the
  orchestrator's, written when B-222 is marked done.

## Found, not absorbed

- **Candidate, no item: a quoted field's trailing newline is a second
  `trim_ws` mismatch that `PARITY.md` row 23 does not list.** Row 23 records
  that metasalmonpy's `trim_ws` approximates readr's. It names one measured
  mismatch, a tab before an opening quote, and says every other probed shape in
  `READR_ROW` agrees. The measurement above is a second mismatch: readr keeps a
  trailing newline inside quotes, and `read_sdp_csv()` strips it. Which side is
  right, and whether row 23 should name it, is a register question. So it is
  reported here, not changed.
- **Not measured: the two known candidates.** One is an IRI carried only by a
  candidate beyond `max_candidates`. The other is one IRI carried twice in a
  slot. This change makes the first carrier in the review the decision row. It
  does not touch what the record or the replay do with a second carrier.
- **Unreachable, measured by reading: a missing candidate IRI renders
  differently in the two ports.** R's `.ms_review_decision_iri(NA)` is `NA`, and
  Python's `_strip_review_iri()` of a missing value is `""`. So for a candidate
  with no IRI, the writer's check would differ. Both review builders drop such
  candidates before any row is queued: `review_console.py` keeps only rows whose
  `iri` is non-empty, and `R/review-console.R` does the same with `has_iri`. So
  no public path reaches the difference.

## Guards added, and what retires them

None. The change adds tests and no suppression, skip, allowlist or workaround.
One test compares where the decision sits before it compares whole frames,
because pandas 3.0.6's `assert_frame_equal` raises a `TypeError` rather than a
diff where a `pd.NA` faces a value. That is an ordering of assertions, not a
guard. The whole-frame comparison still runs.
