## The narrowed test, since the item asks for it

A column seeds a code list only if R would hold it as character or factor:

- **R's guard, read as B-241 reads it.** `_code_list_applies()` accepts a
  Categorical, a string column, or an `object` column of text. So an `object`
  column of `datetime.date` or `datetime` values (R's `Date` and `POSIXct`), or
  of numbers or logicals, seeds nothing.
- **And not text that readr would read as a date or a date-time.** R's seeder
  receives what `readr::read_csv()` typed, and pandas guesses no dates. A text
  column seeds nothing when every present value has readr's date shape
  (`resource_types._DATE_RE`), or when every present value is accepted by
  `readr::parse_datetime()` (`resource_types.parse_datetime_token()`). Blank
  text is missing to readr and is skipped.
- **A Categorical always passes**, as a factor passes R's guard whatever its
  levels. Declaring one is the caller's code-list intent.

The item warned that the obvious candidate, excluding `object` columns of
`datetime.date`, is not enough: the documented path hands the seeder text, not
date objects. The guard above covers the object case, and the readr test covers
the text case. The item's other worry, that a string date column read from a
CSV looks the same as a real code list by dtype alone, is answered by reading
the values, the way readr itself decides.

**Why reuse `_code_list_applies()`:** it is the same R guard, and one reading
of it is better than two. It moved from `dictionary.py` to `metadata.py` with
its body unchanged, because `dictionary.py` imports `metadata.py` and not the
other way round. One risk was measured before reusing it. On raw
`pandas.read_csv` output, pandas' chunked parser could in principle hand over an
`object` column that mixes ints and strings, and this guard would refuse it
where R's character column is seeded. A 400,050-row `RUN_TYPE` column (`FALL`
and `SUMMER` among `1`s), in both orders, came back as uniform text under
pandas 3.0.6 (`str`) and pandas 2.2.3 (`object`, all `str`). readr read it as
`character`.

**Why dates and date-times, and not times of day:** the item is about
date-like columns, and `Date` and `POSIXt` are the two classes R's own temporal
branch names. readr also reads `10:00` as `hms`, but that shape is also a
ratio or a score (readr reads `1:10` as a time too), so copying it would stop
seeding such code lists. That is a judgement, and it is listed below as a
candidate.
