## A side effect, named rather than left to be found

`validate_semantics()` imports `validate_dictionary` and two field lists with
`from .dictionary import ...`. Its `except ImportError:` fallback,
`from metasalmonpy.dictionary import ...`, is marked
`# pragma: no cover - direct module import compatibility`. In this tree the
only code that ran that fallback was `tests/test_validation.py`, importing
`validation` by top-level name under `python -m pytest`, because a module
imported that way has no parent package for the relative import. `git grep`
finds no other top-level import of `validation`, so nothing runs the fallback
now.

This is not a narrowed test, for three reasons. The tests' inputs and
assertions are unchanged. Both branches bind the same objects from
`metasalmonpy.dictionary`. And the route the fallback serves is not one the
package offers, since the wheel installs no top-level `validation` module. The
primary branch was already exercised through `package_io.py`, which calls
`validate_semantics()` via `from .validation import`. Whether the fallback
should stay is a question for its own item. It is listed as a candidate below.
