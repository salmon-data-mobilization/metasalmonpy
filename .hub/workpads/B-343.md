## Changes

`metadata._absolute_iri_shape()` owns the new checks' existing R shape:
ASCII scheme, colon, nonempty suffix without a member of `R_SPACE_CLASS`.
Fullmatch rejects a final LF, matching R's guard; this is not network
resolution or a stricter URI grammar. Existing HTTP authority/placement
checks retain their separate owner.

`validate_dictionary()` checks the same fixed six semantic fields it already
sweeps for REVIEW markers, under `require_iris=True`. A table shape collector
checks every `tables.csv` `*_iri` column, including undeclared extensions,
only in the public package validator's strict path. Table method/protocol
fields stay with their unconditional placement checker to avoid duplicate
shape reports. Blanks and recognized markers remain with existing checks.
Those blank checks mean missing values or exact empty strings for direct
dictionary input. Raw whitespace is present under the existing missing-value
contract and now fails shape. CSV inputs are checked after the reader's
existing ASCII trimming; leading/trailing raw ASCII whitespace can normalize
away. No raw-byte pre-read sweep or reader behavior change is claimed.
Python's current IGNORECASE recognizes dotless-i REVIEW; the control confirms
it is refused once as a marker without performing B-345's separate narrowing.

`tests/test_validation_hardening.py` covers both public validators, six field
names, leading NBSP and malformed text, table observation-unit and custom
fields, valid schemes, blank baselines, non-strict acceptance and single
marker/placement reporting. `CHANGELOG.md` records the observable fix.
