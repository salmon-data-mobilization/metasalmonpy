## The five #121 review findings, each carried across

1. **A degraded lookup aborts; it does not become a gap.** A raised search error
   and the `attrs["diagnostics"]` failed-source signal are both carried back out
   of `_search_evidence()`. An IRI that failed to resolve while any attempted
   search was degraded raises `RuntimeError` **before anything is written**,
   naming the IRI and the sources that did not answer.
2. **Incomplete evidence is a third outcome, not a gap.** `closure["incomplete"]`
   names the IRI, the missing field and the slot, and warns in as many words that
   it is not an ontology gap. Three ways a row can go unwritten; only one makes a
   gap.
3. **All three outputs install as one link-refusing atomic set**, through
   `sdp_methods._atomic_write_set()`, with both sidecar digests computed over the
   bytes *about to be installed* (`_bytes_sha256`) rather than by hashing files
   already on disk — which is what lets the sidecar join the same write set.
4. **Path resolution goes through the package's own hardened layer.** Symlinked
   root, symlinked intermediate component and symlinked final entry are all
   refused, for both closure targets **and the sidecar itself** (a linked sidecar
   would otherwise choose where the closure gets written). **Hard links are
   closed structurally by the staged rename rather than detected**, and
   `_resolve_write_path`'s docstring says so explicitly rather than implying
   coverage.
5. **The degraded-status test is one copy.** `find_terms()`'s warning and this
   producer both read `term_search._search_failed_sources()`.

The ruled **gap-not-abort** shape (Brett, 2026-09-12) is implemented as ruled and
is not softened into an exception on the Python side.

**One of those REDs found a real defect in my own test**, and it is the reason
the atomicity test now ends the way it does. The first draft supplied the
"changed" definition on a `target_sdp_field`-scoped evidence row, which the
vocabulary overlay correctly ignores — so both halves compared identical bytes
against identical bytes and the test passed against a deliberately non-atomic
writer. The fix is the scoped row replaced by a general one **plus a final
assertion that the same call, once unblocked, really does write different
bytes**, so "unchanged" can never again be true for the wrong reason.

## Contracts this had to survive

- **Mirror contract.** A port: no new `PARITY.md` row, no change to the version
  or to what the mirror contract claims.
- **C collation / one value one rendering.** Every cell is coerced to text once,
  by `_closure_text()`, when the row is built; that same string is the sort key,
  the digest input and the CSV byte. Ordering is Python's `sorted()`, which is
  codepoint order. Pinned by
  `…both_files_are_written_in_c_collation_order`, which asserts the written file
  carries the order that was sorted, and by the byte-identity runs above.
- **cli-safety.** Python's half is redaction only (`PARITY.md` row 37 — the
  escape half is deliberately absent because an exception message is a finished
  string). The one piece of external text this producer captures is a search
  exception, redacted with `redact_secrets()` at capture, and
  `…a_raised_search_error_is_redacted_where_it_is_captured` pins it.
- **No LLM on this path.** Pinned by a raising binding on
  `llm_review.request_json` / `_request_json_with_retries`.
- **Every guard says what retires it.** See the next section.

## Two Python-native choices, neither a deviation

Both are language idiom, not behaviour, so no register row is opened. Recorded
here and in the module docstring so a reader does not have to infer them.

1. **Exception classes.** Input problems raise `ValueError` (which
   `SdpExtensionError` already subclasses, so path refusals stay catchable both
   ways); a degraded lookup raises `RuntimeError`, because it is an
   environmental failure a caller retries rather than a bad argument. R signals
   both through one cli condition class because R has no such distinction.
   Reports are `RuntimeWarning`, the class `find_terms()` already uses.
2. **The vocabulary field list is derived, not restated.** R keeps its own
   `.ms_closure_vocabulary_fields()` and pins it against the verifier by
   evaluating the verifier's body, because R cannot import a constant out of a
   function. Python can, so `_VOCABULARY_FIELDS = tuple(eml._VOCABULARY_SNAPSHOT_FIELDS)`
   and the two cannot diverge at all. The test asserts the derivation, so
   replacing it with a literal fails.

## Finding 4022399526 — `guides/semantic-review.qmd:172` — VALID, fixed

The guide described the review-target set as the measurement set *"plus"* each
table's `observation_unit_iri`. That is wrong in one direction: the measurement
set includes code-resolved `sosa:usedProcedure` IRIs and the review-target set
does not, so following the prose adds a ledger row for a procedure.

Verified rather than read: neither implementation's `_canonical_review_targets`
references `_used_procedures` at all (0 occurrences, both sides), and
`eml._read_semantic_review()` enforces an **exact** set — a key not in the
canonical targets is collected as `unexpected` and refused. So the prose would
have a user add a row to make the package validate and thereby stop it
validating.

Fixed by describing the set independently, as the module docstring already does,
and by naming both directions of the difference plus what the ledger gate does
to a row added for a code-resolved procedure.

**This sentence came from metasalmon's own vignette** — I transcribed it from
`vignettes/post-review-package-publication.Rmd`, which still says *"that same set
plus each table's `observation_unit_iri`"*. **R-side candidate** below.

## Finding 4022399520 — `semantic_closure.py:824` — premise is false; answered

The finding says `eml._default_mapping_path()` "explicitly supports
`metadata/eml-mapping.yaml`", so a `.yaml` package is treated as having no
sidecar and `write_eml_from_sdp()` then rejects the files for a digest mismatch.

**`.yaml` is not a sidecar name this toolchain reads.** Both
`eml._default_mapping_path()` and R's `.ms_eml_default_mapping_path()` name
`.yaml` only to refuse a package carrying *both* spellings, and otherwise return
the `.yml` path **unconditionally**. Measured on a package carrying only
`metadata/eml-mapping.yaml`:

| | `write_eml_from_sdp()` |
|---|---|
| Python | `FileNotFoundError: EML mapping sidecar …/eml-mapping.yml does not exist.` |
| R | `Error: EML mapping sidecar … does not exist` |

So the digest-mismatch chain cannot occur: nothing ever reads the `.yaml` to
check a digest against. Treating such a package as having no sidecar is the
**same answer the EML writer gives**, not a disagreement with it — and both
closure producers write byte-identical output in that case, with the `.yaml`
left untouched.

**What is real underneath it, and is shared rather than mine:** with **both**
files present, `write_eml_from_sdp()` refuses the package while the closure
producer quietly uses the `.yml`. Measured identical in R, whose closure producer
also hard-codes the `.yml` path instead of routing through
`.ms_eml_default_mapping_path()`. Byte-identical output from both producers in
that case too. Fixing it on the Python side alone would be a deliberate
divergence needing a register row — which is a class reserved to Brett — so it is
**filed for both sides** and documented in `_mapping_file()` rather than changed
in a port.

No behaviour changed for this finding. `_mapping_file()` gained the measurement
and its retirement condition, so the next reader does not re-derive it.

## The security review that will not run

`HUB.md`-adjacent measurement relayed with the findings: **Codex runs no security
review on this repository** — metasalmon 7 of 7 pull requests have one,
metasalmonpy 0 of 3 (hub **B-190**). The R original's *security* review is what
found the symlinked-output class on #121. So I re-read every path this producer
resolves or writes, adversarially, and **measured** each rather than reasoning
about it:

| Case | Result | Anything written outside? |
|---|---|---|
| Symlinked package **root** | `SdpExtensionError: path must not be a symlink` | no |
| Symlinked **intermediate** component (`metadata/` is a link) | `SdpExtensionError: … refuses to write: metadata/eml-mapping.yml` | no |
| Sidecar declaring an **escaping** path (`../../outside/escaped.csv`) | `SdpExtensionError: … refuses to write` | no |
| Sidecar declaring an **absolute** path | `SdpExtensionError: … absolute closure path` | no |
| Symlinked **final entry** (each of the three names) | `SdpExtensionError: … refuses to write` | no, targets byte-intact |

**My tests covered only the final entries.** The other four are now pinned, in a
section that says why it exists and what retires it. All five are load-bearing:
bypassing `_resolve_write_path()` entirely fails all five, and a narrower RED
that removed only the explicit `_assert_safe_directory` call left them green —
because `_assert_safe_file` does its own directory walk. **Two layers, and the
first RED I wrote was too weak to tell**, which is recorded because it is the
same shape as the vacuous atomicity test earlier in this workpad: a guard test
that passes against a broken guard is worth less than no test.

One residual, not changed: if a sidecar declares the *same* path for both closure
files, the write map collapses to one entry and one file goes unwritten. R
collapses identically (a named-list assignment), the resulting package fails its
own digest check immediately, and it needs the sidecar to say the same path
twice. Named as a candidate rather than diverged on.
