## What changed, and where

- `llm_review.py`, the context block, from the `SUPPORTED_CONTEXT_EXTENSIONS`
  constant to `_relevant_context()`. Each function is named after and
  documented against the R function it follows. The block's header comment
  records the four R facts the code leans on, each measured on 2026-09-25 under
  R 4.5.2: `readLines()` accepts LF, CRLF and a bare CR and discards a UTF-8
  byte-order mark; `trimws()` strips only space, tab, CR and LF; `iconv(sub =
  "")` drops the five bytes Windows-1252 leaves undefined; `[^a-z0-9]` is a
  code-point range and `tolower()` applies the simple case mapping (so the one
  code point whose full lowercase mapping differs, U+0130, is folded first).
  Two R facts were handled rather than copied, as the item asks: the camelCase
  split in `.ms_context_tokens()` never fires because R lowercases first, so it
  is not reproduced; and the tie order pinned is the radix order B-326 gives
  R's scorer, not the locale order its `order()` follows today.
- `llm_review.py`, `assess_semantic_suggestions()`: passes the shortlist and
  the config-dependent excerpt limit into `_relevant_context()`, which now
  scores each target with its own candidates and unions a bundle's picks in
  role order (`.ms_semantic_bundle_context_chunks()`).
- `load_context_chunks()` keeps its signature; `chunk_size` defaults to 2200
  and it gains `overlap=200`. `.ipynb` is no longer read. An unsupported or

## Found, not absorbed

1. **Candidate (metasalmon): `.ms_context_text_from_rmarkdown()` has no
   encoding fallback.** `.ms_read_text_utf8()` re-decodes an invalid UTF-8
   file from Windows-1252, but the `.rmd`/`.qmd` reader calls
   `readLines(encoding = "UTF-8")` directly, which marks bytes without checking
   them, so a Windows-1252 `.qmd` reaches `nchar()` in `.ms_chunk_context_text()`
   and errors with "invalid multibyte string". This package applies the same
   chain to those files and reads what R refuses. Not a difference the fixtures
   can pin (the fixture `.qmd` is UTF-8), and the natural home is B-326's
   scorer work or a backlog item.
2. **Candidate (metasalmonpy): the HTML extractor keeps `<script>` and
   `<style>` text.** `_TextExtractor.handle_data()` collects every data node;
   R's reads body text nodes outside those elements. Row 62 covers it as
   library-specific, but it is the largest practical gap under that row and a
   ten-line fix if convergence is ever wanted.
3. **`_target_key()` uses nine columns where R's group key has eight.** Python
   keys a target's candidates with `search_query`; `.ms_semantic_target_group_cols()`
   omits it. No verdict on the fixtures depends on it.
4. **B-326's radix change retires one line here.** `expected-from-r.R` sets
   `LC_COLLATE=C` so that it records the radix order; once B-326 lands the call
   is redundant and the output does not change. The script says so.
