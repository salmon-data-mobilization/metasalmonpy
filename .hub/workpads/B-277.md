## What changed and where

The rule is enforced in the two places B-276 enforces it in R, from one
predicate.

- **`semantics.py`, `_semantic_code_value_is_empty()`**, new, R's
  `.ms_semantic_code_value_is_empty()`: a missing value, or text blank once
  `scalar_text()` trims it. That trim strips `READR_TRIM_CHARS`, which is what
  R's `trimws()` strips, so U+00A0 and U+3000 stay code values as they do in R.
  `_is_missing()` was not used, because its parameterless `.strip()` would read
  a U+00A0 code as empty where R keeps its target (measured, below).
- **`semantics.py`, the codes loop of target discovery in `suggest_semantics()`**
  (the one place a `codes.csv` target is formed): such a row gets no target in
  any role, so no key is formed for it. Coded rows of the column keep theirs.
- **`review_console.py`, `review_semantics()`**: the `keep` mask drops a row
  whose file is a code's (`_is_code_slot()`) and whose code value the predicate
  reads as empty, never matching on `target_row_key`. So a
  `semantic_suggestions.csv` written before the change queues no slot for it,
  with `include_filled=True` too, and no recorded decision on it is replayed.
- Docstrings of `_match_slot_rows()`, `_review_call_args()` and
  `accept_suggestion()`'s `code_value`, as R's comments and man page changed.
  No signature, return attribute or target-row column changed.
- **Tests**, the twins of B-276's: `tests/test_semantics.py` (new
  `CodesRowWithNoCodeValueTests`) and `tests/test_review_console.py` (the named
  round-trip test rewritten and parametrised, three new tests, and the
  `_vocabulary_code_review()` fixture built as an earlier version built it; on
  the unfixed code it builds a review identical to the old fixture's in rows,
  dtypes and rendering). Every test runs each spelling: NaN, `pd.NA`, `None`,
  empty text and blank text.
- **`CHANGELOG.md`**, under `## Unreleased`.
