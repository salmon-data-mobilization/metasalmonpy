# B-240: metasalmonpy infer_column_role() classifies year-shaped measurement columns as temporal, the mirror half of B-53

The item's fields and retirement condition live in `queue/items/B-240.yaml` on
metasalmon `main`, and this report does not restate them. It was read at
`16976b1`.

## Where each part of the retirement condition is met

1. **The rule B-53 landed in R.** `dictionary.py` now carries the rule that
   merged in metasalmon pull request #152 (`0813cbf`), not an earlier version
   of it. The words decide only whether the year shape may decide, and every
   check after that reads the coarse tokens. Run over the same 64 name and value
   pairs, metasalmon `main` (`16976b1`) and this branch agree on every
   year-shape verdict and every role (*Commands and results*).
2. **The column reaches the semantic pipeline with a measurement role.** With
   the values 1850, 2003 and 1999, `NATURAL_ADULT_SPAWNERS` types `measurement`
   in `infer_dictionary()` and gets 5 semantic targets from
   `suggest_semantics()`, where it got 0. Those are the same targets it gets
   with values off the year range.
3. **A test pins the case against `_values_look_yearish()`, predicate first.**
   `tests/test_year_shaped_measurement_role.py` asserts the predicate is true
   for every year-shaped fixture before it asserts the role.
4. **The fixtures are ones this package's predicate reads as year-shaped.**
   They are `int64`, nullable `Int64`, text and categorical. There is no
   `float64` fixture, because `_values_look_yearish()` never reads a float
   column as year-shaped (*Found, belonging elsewhere*, item 1). The control
   enforces this: a `float64` fixture fails on the predicate, not the role.

## What changed and where

- `dictionary.py`
  - `infer_column_role()`: the temporal branch is split in two. The name and
    type checks come first and are unchanged. The year-shape check,
    `_values_look_yearish(series)`, now returns `temporal` unless the name's
    words include a measurement word, or a sample or partition size, and no
    time word. Everything after it, the branch order included, is unchanged.
  - New `_name_words()`: the tokens split again at every ASCII punctuation
    character. The class is built from `string.punctuation`, which is the same
    32 characters as the four ranges R spells out, and the test checks it
    against those ranges over all printable ASCII.
  - New `_name_has_measurement_word()`: `_MEASUREMENT_TOKENS` membership or
    `_name_has_sample_size_hint()`, and neither of the hint's two pattern
    tests.
  - New `_YEAR_SHAPE_TIME_WORDS`: `_TEMPORAL_TOKENS` plus `years`, `yrs`,
    `months` and `days`. The plurals are kept out of `_TEMPORAL_TOKENS` itself,
    as in R.
  - The docstring of `infer_column_role()`, which is public here (`PARITY.md`
    row 42), states the rule.
  - R's change also moved its two word lists into `.ms_measurement_name_tokens()`
    and `.ms_temporal_name_tokens()`, so that each has one home. There is
    nothing to port there, because `_MEASUREMENT_TOKENS` and `_TEMPORAL_TOKENS`
    were already single module-level constants.
- `tests/test_year_shaped_measurement_role.py` (new, 41 tests): the R file's
  seven blocks case for case, parametrised per fixture. The one addition is the
  boundary check in the word-split test.
- `CHANGELOG.md`: one entry under `## Unreleased` / `### Fixed`.

## Found, belonging elsewhere

1. **Candidate (metasalmonpy, and which side is right is a ruling):
   `_values_look_yearish()` never reads a `float64` column as year-shaped,
   where R's reads a double column as year-shaped.** `_character_values()`
   renders through `str()`, and `str(1850.0)` is `"1850.0"`. Measured on this
   branch from the same CSV text (`BY,NATURAL_ADULT_SPAWNERS` /
   `2001,1850` / `,2003` / `2003,1999`): pandas reads `BY` as `float64` and this
   package types it `attribute`, while readr reads a numeric `BY` and R types it
   `temporal`. The corpus has a live instance, `method_version` above.
   `PARITY.md` row 35 widens the reach, because a declared `integer` column
   reads back as `float64` through this package's own readers. B-53's workpad
   recorded this as its candidate 2, and B-240's condition keeps it out of this
   item.
2. **metasalmon's records of the owed port.** When this merges, the B-53 port
   entry in metasalmon's `knowledge/parity-deviations.md` (the paragraph
   beginning "The development version after 0.5.0 adds to what the port owes
   (2026-09-24)") and its matching entry in the `knowledge/roadmap.md` release
   index will still say the port is owed. B-202 covers the class.
3. **Candidate (metasalmonpy): `infer_column_role()` does not treat an object
   column of `datetime.date` as temporal, where R's treats a `Date` as
   temporal.** Python checks only `is_datetime64_any_dtype()`, and R checks
   `inherits(col, "Date") || inherits(col, "POSIXt")`. Measured: `observed` with
   two `datetime.date` values types `categorical` here and, as a `Date`,
   `temporal` in R, while `infer_value_type()` says `date` on both sides.
   `infer_value_type()`'s own docstring says an object column of
   `datetime.date` is this package's counterpart to R's `Date` and is what
   `resource_types` produces for a declared `date` column. `PARITY.md` does not
   mention it.
4. **Mirrored, not new:** B-53's candidate 6, that role inference cannot see
   words joined by punctuation and that fixing it for every check is a design
   question, holds here as well. The unit and rate test block is the check any
   fix must keep passing.

## Guards added, and what retires them

- **The narrowed year-shape check** is heuristic logic, not a suppression. Its
  whole-word restriction retires when the measurement hint's substring and unit
  patterns stop matching `temporal` and bare-`g` parentheticals (B-53's
  candidate 3). The exemption could then use the full hint. The substring and
  unit test block is the check that such a change is safe.
- **The boundary check in the word-split test** pins the split to R's four
  ASCII ranges. It retires only if R's set changes, and then both change
  together.
- **The unit and rate test block** retires into the tokenizer question
  (item 4 above), as its R counterpart does.
- No skip, suppression or allowlist was added.
