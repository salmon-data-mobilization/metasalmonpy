## Found, not absorbed

1. **Candidate: for the text `999-06-05`, the two implementations write
   different `datapackage.json` temporal values.** metasalmonpy keeps
   `999-06-05`: `_descriptor_temporal_text()` sends text to `_clean()`,
   measured above on `0235487`. metasalmon writes `0999-06-05`: its
   `.ms_descriptor_temporal_text()` sends text through `.ms_iso_character()`,
   which pads a one-to-three-digit year, measured in B-162's workpad on
   metasalmon `372ef07` (R 4.3.3). B-162's workpad recorded only the R-internal
   half, as its candidate 2: R's two writers disagree with each other, where
   metasalmonpy's agree. The cross-implementation half is not in the parity
   register: `knowledge/parity-deviations.md` on metasalmon `df3abd3` has no
   row naming `999-06-05` or short-year text, and rows 40 and 56, the nearest,
   concern typed values and instants. The value is off-profile, so B-204 and
   B-205 would refuse it at validation, but only after both writers had
   written it. Which side is right is a ruling, not a mirror.
2. **Candidate: B-162's candidate 1 holds in metasalmonpy as well.** A typed
   instant's three copies agree (`2024-01-01T00:00:00Z`), and
   `write_eml_from_sdp()` refuses the document at its schema check, because
   EML 2.2.0's `calendarDate` is `xs:gYear | xs:date` (measured above). The
   profile admits the instant. No queue item on metasalmon `df3abd3` covers
   this. Eighteen item files there mention EML in any case, and only B-162's
   mentions an instant; it closed by design and recorded this as a candidate
   without filing it. How an EML should carry an instant is a design question
   for an outward-facing format.
3. **The short-year test depends on validation accepting `999-06-05`.** B-205
   would enforce the schema's temporal pattern in
   `validate_salmon_datapackage()`, which refuses that value. The test's
   docstring names the move to make then: take the frame from
   `read_salmon_datapackage()`, which validation returns unchanged, as
   metasalmon's twin does.
4. **metasalmon names this item as owed in two places**, on `df3abd3`:
   `knowledge/parity-deviations.md` lines 907 to 946, under *What metasalmon
   0.5.0 owes the mirror* (the id at 946), and `knowledge/roadmap.md` lines 643
