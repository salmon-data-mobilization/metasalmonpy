## What changed, and where

- **`review_console.py`, `accept_suggestion()`.** The `if not accepted_iri:
  raise ValueError(...)` moved out of the `iri is not None` branch, which ran
  before `_strip_review_iri()`, to just after it. It still applies only when

  passed was not blank, the message adds *"An accepted IRI is recorded without

- **`tests/test_review_console.py`.** `MARKER_ONLY_IRIS` and the parametrized
  `test_accept_refuses_an_iri_that_is_only_the_review_marker`, plus the control
  `test_accept_takes_a_marked_iri_and_records_it_without_the_marker`, mirroring
  metasalmon's `tests/testthat/test-review-console.R`.
- **`CHANGELOG.md`.** An entry under `## Unreleased`, `### Fixed`.
- **`AGENTS.md`.** The dated suite counts under *Build / test* now lead with
  this branch's measurement, which that section asks for whenever tests are
  added. B-241's moves into the history.

**Why these seven spellings.** Each reaches an empty result by a different
route through the strip:

- `"REVIEW:"`, the bare marker. This package writes the marker without a space
  (`package_io._mark_review_iri()`).
- `"REVIEW: "`, the marker as metasalmon writes it (`.ms_review_iri_prefix()`),
  whose space `scalar_text()` trims.
- `"review:"` and `"Review:"`, case, through `str.upper()`.
- `"  REVIEW:"`, leading whitespace, which `scalar_text()` trims
  (`READR_TRIM_CHARS` is space, tab, CR and LF).
- `"REVIEW:\f"`, whitespace after the colon that the trim leaves and only the
  strip's `str.strip()` removes. Twenty-five code points are in that class
  (listed below). R's strip removes the form feed too, in either locale, which
  is why it stands for the class here. The Q-63 table below shows where the
  two strips part.
- `"REV\u0131EW:"`, a dotless i, which `str.upper()` folds onto `I`. An
  enumeration of every code point found it to be the only non-ASCII character
  that folds onto a letter of the marker.

R's list also has a space and a tab before the colon. This strip leaves both,
so they are not here; that difference is Q-63's.

## Found, not absorbed

- **For Q-63:** the table above. Q-63's evidence lists each package's detector
  sites. It does not record that the two strips' whitespace and case-folding
  sets differ, in both directions, or that R's depends on the locale.
- **Candidate, no queue item: a doubled marker survives a decision.** In
  metasalmonpy, `accept_suggestion(iri="REVIEW:REVIEW:")` records
  `decision_iri` `"REVIEW:"`, on `85ebbb0` and on `acf243e` alike. That goes
  against `_strip_review_iri()`'s docstring, *"`REVIEW:` never survives a
  decision"*. R's strip leaves `"REVIEW:"` for the same input on `1e264d4`
  (R 4.3.3, both locales), so R's accept path probably shares it. R's accept
  was not run. Not fixed here, because the result is not an empty IRI and the
  fix would belong to the strip rather than to the check.
- **Candidate, no queue item: `review_semantics()` reports a suggestion row
  with an empty `iri` as a field it "cannot decide".** Its `keep` mask in
  `review_console.py` drops a row whose `iri` is empty along with rows that
  have no write-back address. It then lists the dropped rows' fields under
  *"Some suggestions target fields this review cannot decide, and are not
  queued ... Edit those in the metadata CSVs directly."* For the empty accept
  above it named `column_dictionary.csv · term_iri`, a field the review decides
  (measured on `85ebbb0`). This branch closes the route by which
  `accept_suggestion()` wrote such a row. A package the defect already wrote,
  or a hand-edited CSV, still prints it on every review. R was not measured.
