## Ported, not vendored, and what keeps the two copies one

**Ported.** The hub's `scripts/check-changelog-window.py` is git blob
`f984c4c603eb2fd4df9eb421d71695cb82de1bad`, as its pull request #173 merged it
(`f8681c0`), and it is unchanged on metasalmon `main` `97db837`. It could not be
vendored byte for byte, for three reasons, each in the code:

- it reads this repository only as a sibling (`METASALMONPY_PATH`, else
  `../metasalmonpy`), so a byte copy here would check nothing unless told
  `--profile metasalmonpy --repo .` every time;
- its `metasalmonpy` profile leaves `tagged_from` unset, pending this item;
- it has nowhere to hold a ruled exemption.

So the port is that blob with one profile, `PROFILE`, read from this checkout;
`tagged_from="0.3.0"`; the ruling (`Ruling`, `RULINGS`, `corrections()`, and
the lines in `run()` that apply it and report it); a `main()` without
`--profile`; `import os` dropped with the only line that used it; and a
rewritten docstring. `diff` against the
blob shows nothing else.

**What keeps them one** is `TestTheHubCopy`. It parses both files and compares
every top-level definition by syntax tree (`ast.dump`, so comments and
positions do not count and docstrings do). It fails on a definition the hub has
and the port lacks, on one the port has that is not declared, on a shared one
that differs, and on a declared difference that has stopped differing.
`DIFFERS` in the test file declares seven names, each with its reason. The
workflow clones the hub's `main` and runs it with `CHANGELOG_WINDOW_STRICT=1`,
so a change to either copy is red here until the other follows. Shown red all
four ways, on scratch copies:

| change | result |
|---|---|
| the hub's `split_lines` uses `str.splitlines()` | `split_lines: differs from the hub's copy.` |
| the hub gains `a_new_helper()` | `a_new_helper: the hub's copy defines it and this one does not.` |
| the hub's `main` becomes the port's | `main: declared in DIFFERS, and the two copies match. Remove it from DIFFERS.` |
| the port's `closing` gains `or False` | `closing: differs from the hub's copy.` |

What it does not do: the hub's CI does not run it, so a change to the hub's
copy goes red here and not there. That is a candidate below.
