## What changed, and where

- **`sdp_schema.py`: new `_sdp_schema_options_are_default()`.** The twin of
  R's `.ms_sdp_schema_options_are_default()`. It is true when
  `default_sdp_schema_source()` is `"auto"` and `default_sdp_schema_base_url()`
  is `DEFAULT_SDP_SCHEMA_BASE_URL`. It compares resolved values, so a setting
  that names the default is the default, and so is an empty environment
  variable, which the resolvers read as unset.
- **`sdp_field_setters.py`: the constant `_SCHEMA_SOURCE = "vendored"` becomes
  the function `_schema_source()`.** It returns `"vendored"` under the shipped
  settings and `None` otherwise. `None` means the loader's own resolution,
  which is what the writers read. All five schema reads in the module call it,
  so the scan and the setters still read one parse. The module docstring and
  the `review_metadata()` docstring now scope the offline promise to the
  shipped settings, as R's roxygen has since B-175. The `set_sdp_dataset()`
  docstring now says the setters read the same schema; the other three setters
  point at it.
- **`sdp_field_setters.py`, `_set_sdp_metadata()`: the written frame is
  aligned to `declared`**, the field names the setter checked the values
  against, as R's setter has done since B-175 (`.ms_align_cols(frame,
  declared)`). It used the static `_ALIGN_COLUMNS`, so under a selected schema
  that declares a field mid-list, the setter accepted the field and then wrote
  it at the end of the header. This does more than reorder. Under a selected
  schema, any setter call adds each declared column the file lacks, empty, as
  R's setter does. Under the bundled schema the static lists equal the
  declared order in all four files, measured with
  `sdp_schema_field_names(name, source="vendored")`, so no bytes change there.
  `_ALIGN_COLUMNS` and its four imports had no other reader in the module and
  are removed.
- **The writers follow the same order.** `_declared_metadata_fields()` and
  `_in_declared_order()` in `sdp_field_setters.py` align a frame to the
  fields the selected schema declares, with any other column after them.
  `write_salmon_datapackage()` serialises its four metadata files through it,
  and so does `apply_sdp_semantics()`, whose `metadata_write._ALIGN_COLUMNS`
  is removed with the imports only it used. This ports R's writers, which
  align through `.ms_align_cols(df, .ms_dataset_meta_cols())` and its
  siblings, reading the session schema (`R/package-helpers.R:2063-2104`,
  `R/metadata-write.R:124`). Under a selected schema, a fresh write gains that
  schema's declared columns, empty, as R's writers add them.
- **`package_io.py`, `_collect_blank_required_metadata_fields()`:** imports
  and calls `_schema_source()` in place of the constant, and its docstring
  says so.
- **`tests/test_sdp_field_setters.py`:**
  - `_use_shipped_schema_defaults()` clears both settings and both environment
    variables, empties the caches, and asserts the resolved defaults. That is
    what R's `local_shipped_schema_defaults()` does with its three options.
  - `test_a_schema_the_settings_select_is_the_one_the_scan_and_the_setters_read`
    is the twin, parametrised over the four routes. The writers' own read
    (`load_sdp_schema(fetch_fn=...)`) loads a bundle that adds a required
    `dataset.csv` field, `funding_source`. The test asserts that the writers'
    field list has the field, and then that the scan reports it, the collector
    names it and `set_sdp_dataset()` accepts it. Once the field is set, the
    scan and the collector both clear it. No fetch and no socket are allowed.
  - `test_a_selected_schema_nothing_has_loaded_is_loaded_once` is R's second
    half, over the same four routes. Nothing has loaded the schema yet. The
    scan, the collector and the setter together cause exactly one fetch, from
    `default_sdp_schema_base_url()`.
  - `test_the_shipped_settings_are_told_apart_by_what_they_resolve_to` is the
    twin of R's table test, with 14 cases.
  - `test_a_setter_writes_the_file_in_the_selected_schemas_field_order` puts
    `funding_source` straight after `creator` in a selected schema and asserts
    that the header `set_sdp_dataset()` writes equals the declared order.
    Before the alignment change it failed at index 4, `'contact_name' !=
    'funding_source'`.
  - `test_a_rebuild_and_an_apply_keep_the_order_a_setter_wrote` uses a
    selected schema that declares `funding_source` after `creator` and
    `measurement_note` after `column_description`. It sets both fields with
    setters, rebuilds with `read_salmon_datapackage()` and
    `write_salmon_datapackage()`, and applies one decision with
    `apply_sdp_semantics()`. It asserts that every header equals the declared
    order and that the rebuild writes the setters' bytes. `_bundle_with_fields()`
    and `_header()` are its helpers.
  - The two existing offline tests call the helper instead of their five
    inline lines. The helper does everything those lines did and also clears
    the base URL. Before this branch the base URL never reached the scan. Now
    it does, so a `METASALMONPY_SDP_SCHEMA_BASE_URL` left in a developer's
    environment would have turned both tests red for a reason that has nothing
    to do with the offline promise.
- **`guides/semantic-review.qmd`:** the `review_metadata()` paragraph said it
  "never contacts a network" and reads "the bundled copy rather than the
  remote one". It now scopes both to the shipped settings and names the four
  ways of selecting a schema.
- **`CHANGELOG.md`:** an entry under `## Unreleased`, *Fixed*.
- **`AGENTS.md`:** the dated suite counts.

The Python loader keeps its bundled read outside the loader's one cache slot,

## Found, not absorbed

- **Candidate, no queue item: `sdp_schema_fields()`'s docstring says the
  default source "fetches six documents over HTTP".** `_fetch_remote_sdp_schema()`
  requests eight: the six in `SDP_METADATA_SCHEMA_PATHS`, then the profile,
  then `sdp.rules.yaml`. That is the count metasalmon's B-175 measured for R.
  The comment on `_SCHEMA_SOURCE` said "six" too; the docstring that replaces
  it here states no count. Not fixed, because that docstring is outside this
  item.
- **Candidate, no queue item: a static field that a selected schema removes
  is still written.** The writers now add and order the selected schema's
  declared fields, but they align frames that `normalize_dataset_meta()` and
  its siblings have already filled with the static column lists. So a field in
  those lists that a selected schema does not declare is written after the
  declared ones, empty. R's writers align to `.ms_dataset_meta_cols()` alone
  and would not write it. Found by reading both sides, and neither was run
  under such a schema. Matching R means changing `normalize_*()` in
  `metadata.py`, which `read_salmon_datapackage()` shares.

## Guards added, and what retires them

`_schema_source()`'s first branch carries over the bundled read that
`_SCHEMA_SOURCE` was. It retires when `load_sdp_schema()` stops fetching on its
default source, as its docstring says, which is the condition the constant
had. The tests are pins, not guards: no skip, suppression or allowlist was
added.
