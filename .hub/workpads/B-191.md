## The defect, re-measured before anything changed

The item asked for a re-measurement: the orchestrator could not reproduce it,
and the 908/907 figures were B-165's. Every run below used Python 3.11.15 and
pandas 3.0.6 in a fresh venv with nothing else installed, ran
`python -m pytest -q` from the checkout root as CI does, and added
`-p no:cacheprovider`.

**There are two mechanisms, and they fail in opposite directions.** The
repository root carries the flat-layout `__init__.py`, so pytest treats it as a
package and imports it under a name derived from the directory:

- **A directory name that is not a Python identifier**, which every hub key is,
  makes `resolve_package_path()` stop below the root (`if not
  parent.name.isidentifier(): break`). The root's `__init__.py` is then
  imported as a bare module named `__init__`, and its relative imports fail.
  Under pytest 8 and later the root is a `Package` node in every test's setup
  chain (`Package.setup()` calls `importtestmodule(self.path / "__init__.py")`),
  so **every test errors**. pytest 7 does not put the root in the setup chain,
  so it is unaffected.
- **A name that is an identifier but not `metasalmonpy`** imports the root a
  second time under that name, while `import metasalmonpy` goes to whatever is
  installed. **This one is silent**: the run goes green against a different
  tree. B-144's workpad describes this producing "plausible wrong numbers".

## Why not one of the one-line fixes B-165 proposed

B-165's workpad proposed that "a fix is one line", naming
`consider_namespace_packages`, removing `tests/__init__.py`, or
`--import-mode=importlib`. **None of them works**, and the reason is the
`Package.setup()` import above, which none of them touches. Measured on an
export of `3f8349a` under the hub-key name, CI's shape, pytest 9.1.1, over
`tests/test_atomic_io.py` and `tests/test_public_api.py`:

| Variant | Result |
|---|---|
| unchanged | 15 errors, `attempted relative import with no known parent package` |
| `tests/__init__.py` removed | 15 errors, same |
| `consider_namespace_packages = true` | 15 errors, same |
| `--import-mode=importlib` | 15 errors, same |
| `tests/__init__.py` removed **and** `--import-mode=importlib` | 15 errors, same |

**Setting `--confcutdir=tests` in `addopts` was rejected on reading**, although
it would keep the root out of the tree. pytest resolves a relative
`--confcutdir` against the *invocation* directory, not the rootdir
(`absolutepath(invocation_dir / confcutdir)`). It would work from the
repository root. Launched from inside `tests/`, it would silently stop loading
`tests/conftest.py`, because that directory would then sit outside the cut.

## Tests that can fail

The guard was run from a directory named **`metasalmonpy`**, the name CI uses,
with an editable install that points at a *different* checkout. That is the
situation that produced wrong-tree runs.

| Tree under test | in-process test | copy named with the hub key | copy named `checkout` |
|---|---|---|---|
| fix intact | pass | pass | pass |
| **unfixed `3f8349a` plus only the guard file** | pass | **FAIL**: relative import | **FAIL**: `metasalmonpy was imported from …/salmon-data-mobilization-metasalmonpy-B-191/__init__.py, not from the checkout these tests live in` |

The second row is the one that matters: **on today's `main`, the guard is RED

three measures is pinned by at least one case. A restored `tests/__init__.py`
is caught only by the identifier name, which is why there are two names and
not one. The guard adds about 2 seconds to the suite.

## Guards added, and when each retires

- **The conftest's three measures**: the binding, the root collected as a
  directory, and no `tests/__init__.py`. They retire when the package moves
  into its own `src/metasalmonpy/` directory, so the checkout root stops being
  a package. That is the retirement condition the old AGENTS.md note named.
- **The `hasattr(pytest, "Dir")` condition** retires when the `[test]` extra's
  floor reaches pytest 8.
- **The conftest's refusal to load when `metasalmonpy` was already imported
  from another file** retires with the binding.
- **`tests/test_import_route_guard.py`** gets rewritten, not deleted, when the
  package moves to `src/`. The property it pins, that the suite tests the tree
  it lives in, still holds after the move.
