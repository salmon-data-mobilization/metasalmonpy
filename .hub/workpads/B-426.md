## Found, not fixed (filed as B-436)

Both measured on metasalmon `main` at `4686d93` against this tree, and present
in R no later than 2026-09-25 (the oldest commits `git log -S` returns for
either name are the merges `ef46094` and `a18148e` of that day). Neither
register names either difference.

1. **The method role for a procedure-named column's codes.** R's code-target
   discovery (`R/semantic-suggestions.R`, `parent_names_procedure`) gives the
   codes of a non-measurement column the `method` role when the column's name,
   label or description matches
   `\b(method|protocol|procedure|gear|estimat\w*|enumerat\w*|technique|survey type)\b`,
   and `entity` otherwise; `semantics.py` here gives every non-measurement
   column's codes `entity`. For `ENUMERATION_METHODS` that is `method` in R and
   `entity` here, which the probe on this tree showed (`dictionary_role` of
   the Fence rows: `entity`; the column's `column_role`: `categorical`). The
   twin reads the role back from the suggestions rather than spelling it.
2. **The create-time review-context filter.** R drops a code-scope row whose
   code has no description and whose label is empty or equals its value, case
   folded (`.ms_code_target_has_review_context()`), from the
   `semantic_suggestions.csv` that `create_sdp()` writes; this package writes
   every row. B-120 is evidence that the filter hides work, so which side moves
   is an open question for the ruling, not assumed here.
