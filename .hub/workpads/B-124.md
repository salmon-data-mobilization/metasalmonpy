## What changed, and where

`package_io.py`

* `_package_metadata_frames()` — new. Mirrors `.ms_package_metadata_frames()`:
  one spelling of the four metadata frames with their issue category, source
  name and identifying fields, so a message and its issue row cannot name
  different files.
* `_collect_blank_required_metadata_fields(package, keys=False)` — new. Mirrors
  `.ms_collect_blank_required_metadata_fields()`. Reads
  `sdp_schema_required_field_names()` (the bundled schema, never the remote one
  — the validator makes no network call) and splits it against
  `METADATA_KEY_FIELDS`. A column the file does not have is blank in every row,
  in all four files. Deferred import of `sdp_field_setters`, because that module
  already reaches back into this one the same way.
* `_validate_optional_sdp_semantic_artifacts(path)` — new. Mirrors
  `.ms_validate_optional_sdp_semantic_artifacts()`: calls `validate_sdp_sssom()`
  and `validate_sdp_measurement_decompositions()` when their managed files are
  present. Presence is by file name, never by scanning `metadata/semantic/`; a
  dangling symlink counts as present.
* `_collect_missing_table_observation_unit_iri_issues()` — an absent
  `observation_unit_iri` column is now blank in every row rather than no rows at
  all.
* `_collect_package_validation_issues()` — two additions. Blank **key** fields
  become typed issues in every mode. Blank **non-key** required fields warn in
  the default mode, on the placeholder channel. Tidy check 4: a column the
  dictionary declares `required` and that ships missing values becomes a
  `columns` issue.
* `validate_salmon_datapackage()` — calls
  `_validate_optional_sdp_semantic_artifacts()` after the observation-structure
  check; appends the blank non-key required messages to the strict-mode issue
  list; the strict-mode advice line now names blank schema-required fields;
  docstring rewritten to say what the function checks, mirroring R's.

`tests/test_validation_hardening.py` — eight new tests plus one new differential
fixture case and one amended one (below). `CHANGELOG.md` — one `Fixed` entry.

## Guards added, and what retires them

Nothing here suppresses, skips or excludes a signal, so nothing needs a
retirement condition on those grounds. Two things are load-bearing enough to
say what would end them:

* The **deferred import** of `sdp_field_setters` inside
  `_collect_blank_required_metadata_fields()` exists only to keep `package_io`
  free of a module-level dependency on a module that imports it back.
  *Retires when:* `METADATA_KEY_FIELDS` / `METADATA_SCHEMA_TABLES` move to a
  module both can import at the top level.
* The **`_SCHEMA_SOURCE = "vendored"` read** is the no-network guarantee, not a
  performance choice. *Retires when:* `load_sdp_schema()` stops fetching on its
  default source — the same condition `sdp_schema.py` already records.

## Codex round on pull request #29 (2026-09-16)

One P2 finding, verified before fixing, and it held. Fixed in `1773e3b`.

**The finding.** `value_type` and `column_role` are `constraints.required`
non-keys of `column_dictionary.csv`. This change warns for them in the default
mode, and then `validate_dictionary()` rejected the retained empty string as an
invalid enum — so `require_iris=False` still raised for two of the very fields
the change documents as warn-by-default.

**Reproduced**, blanking one dictionary row of the shipped example:

```
blank value_type,  require_iris=False -> ValueError: Invalid value_type in rows [3]: ['']
blank column_role, require_iris=False -> ValueError: Invalid column_role in rows [3]: ['']
```

**What decided the remedy: R, on the same directories.** metasalmon 0.5.0
returned with the warning and raised only under strict. R warning while Python
raised makes this the **port being incomplete**, not a design choice, so Python
moved and the contract sentence stands. Had R raised too, the contract sentence
would have been the thing that was wrong and both sides would have had to move,
which is not one agent's call.

**Cause.** `read_sdp_csv()` keeps an empty CSV cell as `""` where R's
`.ms_read_metadata_csv()` reads it as `NA`, and R's enum check exempts `NA`
explicitly. A blank never reaches R's check; it reached this one and was
rejected as an invalid *token*. The enum checks now read a blank as **absent**,
the same reading the `required` check three blocks below already applied.

**After**: warns by default, errors under strict, and `'bogus'` is still refused
in both modes. Pinned by
`test_a_blank_required_enum_warns_by_default_like_every_other_blank`. Both legs
green: 804 core, 917 extras.
