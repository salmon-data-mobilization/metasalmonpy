## Found, not absorbed

None of these has a queue item, as far as `queue/items/` on metasalmon
`origin/main` shows.

1. **Candidate, metasalmonpy: the `code_label` defect has a live second
   symptom.** For a column with `column_role` `categorical` and non-string
   code values, the defensive branch turns the column into strings, and the
   categorical-role block then blanks the *listed* values. That happens
   silently apart from a `Pandas4Warning`. Measured: an `integer` column
   `["1","2","3"]` with code values `[1, 2]` comes back `[nan, nan, nan]`,
   although this branch names only `3`. The block is Python-only; R has none.
2. **Candidate, parity: a numeric-typed column with a code list.** R leaves it
   untouched and unreported, even for an unlisted value. Python blanks every
   value whose type differs from the code values' type (row b). Which side is
   right is a ruling. The mirror contract says a divergence opens that
   question rather than settling it.
3. **Candidate, both implementations: a vocabulary-backed codes row.** The
   schema allows an empty `code_value` with a `vocabulary_iri`. Such a row makes
   the codes step treat the column as an enumerated list, so it blanks every
   present value. After B-55 and this item that is reported rather than silent,
   in both implementations. Beside enumerated rows for the same column, R's
   `factor()` aborts on the label count.
4. **Candidate, metasalmonpy, small:** the non-strict coercion warning names
   neither the column nor the values: `Coercion to integer failed; keeping as
   string`. R's now names both.
5. **Candidate, metasalmonpy, small:** a data frame that repeats a column name
   has every value of that column blanked by the codes step, listed ones
   included. This branch leaves that path as it was (guard below).
