## Two choices the item left open, and how each was settled

**1. The writer: `atomic_io.atomic_write()`.** The item said to pick one existing
writer and say which. Either `atomic_io.atomic_write()` or a one-entry
`sdp_methods._atomic_write_set()` satisfies render-to-bytes-then-rename. I chose
`atomic_write()` for three reasons:

- It is the writer the retirement condition itself names ("install through the
  `atomic_io.py` writer"), so meeting the condition needs no interpretation.
- For a single file it is the stronger install. `atomic_write()` is one
  `os.replace` onto the destination, so there is never a moment with no file
  at the path. The one-entry write set renames the original aside to a backup
  first and then renames the stage in, which leaves a gap between the two
  renames. That backup exists so a multi-file group can roll back, and a single
  file has no group to roll back.
- It is already the package's single-file artifact writer (reproducibility
  manifest, decompositions, KNB manifests).

The refusals the write set adds are covered anyway. A symlinked sidecar or
`metadata/` is refused by `create_sdp()`'s existing
`_assert_managed_paths_contained()` before any write. A directory at the path
makes `os.replace` raise, with nothing destroyed. The three stay **three
transactions**, for the R half's reasons.

**2. The EDH path: keep the disk read and move it inside the transaction.** I
did not build from memory the way R does. It now reads, renders, and then
installs, so a read or parse failure anywhere in the package leaves the
previous XML in place. The in-memory frame is not what the package says. I
measured it rather than assumed it: with caller-seeded dataset metadata, a
`temporal_end` Timestamp renders as `2002-06-30 00:00:00` from
`artifacts["dataset_meta"]` and as `2002-06-30` from the re-read package. The
two differ in `gml:endPosition`, and are identical when nothing is seeded.
Switching frames would have changed the XML.

**The renderers go through the writer each file always used.** This is R's
rule, and it matters for a Python-specific reason. `Path.write_text` opens the
file in text mode, which translates `"\n"` to `os.linesep`, so
`text.encode("utf-8")` is not the same bytes on Windows. So the README and EDH
renders call the real write into a `tempfile.TemporaryDirectory()`, exactly as
R's `.ms_sdp_extension_text_bytes()` and `.ms_edh_hnap_xml_bytes()` use
`tempfile()`. The CSV render is `DataFrame.to_csv(None, ...)`, which is the
package's existing convention (`_metadata_csv_bytes()`), and a test pins it
against a direct path write. It is deliberately not `_metadata_csv_bytes()`,
which renders logicals as `TRUE`/`FALSE`.

## Guards, suppressions and workarounds added, and what retires each

- **`test_no_create_owned_sidecar_is_written_by_a_direct_filesystem_call`.**
  Its scope is exactly `create_sdp()` and `_write_review_readme()`, and it says
  so. *Retires when:* the three sidecars are rendered into one write set that
  owns the only filesystem handle, or `create_sdp()` stops writing files of
  its own.
- **Its two exemptions, `.unlink(` and `.mkdir(`.** Each is asserted to be
  *reached*. Each retires with the guard, or when its call leaves
  `create_sdp()`, at which point the reached-assertion fails and says so.
- **`test_suggestions_csv_bytes_match_a_direct_to_csv_write`.** *Retires
  when:* `semantic_suggestions.csv` stops being rendered through
  `DataFrame.to_csv`.
- **The fixture's warning filter**, narrowed from a blanket `ignore` to exactly
  the two messages a fresh seeded package always raises. *Retires when:*
  `create_sdp()` stops warning about a fresh package's review values, or the
  fixture seeds a package with none.
- **The happy path's frozen date**, which works around the EDH XML stamping
  `date.today()`. Without it, two creates straddling midnight would differ for
  a reason unrelated to atomicity. *Retires when:* the create-time EDH XML
  stops depending on the wall clock.
